## 2. 概述

### 2.1 背景

语音助手系统需要同时支持离线和在线语音命令识别两种模式。为了提供更好的用户体验和系统灵活性，需要一个智能路由中间件来协调这两种模式的命令处理。

### 2.2 目标

本模块旨在提供一个可配置的命令词路由处理机制，实现以下目标：
- 支持离线/在线命令词的智能路由和调度
- 无需关注具体的命令词,默认离线与在线的命令词信息一致
- 提供灵活的配置化策略，无需修改代码即可调整处理逻辑
- 保证系统在不同网络状态下的可靠性和响应速度
- 支持多种相似命令词的统一处理

## 3. 核心功能

### 3.1 配置化架构

用户可在系统初始化时通过配置表完成以下设置：
- 通用的命令词处理策略

**优势**：后续需要修改命令词或调整处理策略时，只需更新配置表，无需修改代码。

### 3.2 多种路由策略

系统支持以下三种路由策略：

#### 策略1：在线优先模式（默认）
```
条件判断：
├─ 设备已连接云端大模型服务？
│  ├─ 是 → 使用在线命令词结果，丢弃离线结果
│  └─ 否 → 使用离线命令词处理
```
**适用场景**：希望充分利用云端大模型能力，但在网络不可用时保证基本功能。

#### 策略2：纯离线模式
```
固定使用离线命令词处理，不依赖网络连接
```
**适用场景**：注重隐私保护、网络受限环境，或需要快速响应的场景。

#### 策略3：超时降级模式
```
条件判断：
├─ 设备已连接云端大模型服务？
│  ├─ 是 → 等待在线结果
│  │  ├─ 在超时时间内返回（默认3s）→ 使用在线结果
│  │  └─ 超时未返回 → 降级使用离线结果
│  └─ 否 → 直接使用离线命令词处理
```
**适用场景**：平衡响应速度和在线能力，避免因网络延迟导致用户等待过久。
