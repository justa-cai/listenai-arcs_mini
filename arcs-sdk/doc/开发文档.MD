## 环境搭建

### 自动搭建
1. 运行脚本`prepare_listenai_tools.sh`下载开发工具包
```
./prepare_listenai_tools.sh
```
2. 运行脚本`prepare_toolchain.sh`下载工具链
```
./prepare_toolchain.sh
```
### 手动搭建
1. 下载对应平台的工具链后进行解压,如果已经存在工具链,此步骤可跳过
    + [linux下载地址](https://iflyos-external.oss-cn-shanghai.aliyuncs.com/chip_arcs/listenai-linux-amd64-tools.tar.gz)
2. 下载对应平台的listenai开发工具包
    + [linux下载地址](http://listenai-firmware-delivery.oss-cn-beijing.aliyuncs.com/ARCS/tools/dev-tools/linux-amd64/v0.0.1/listenai-tools.tar.gz)
3. 设置环境变量
    + 将`NUCLEI_TOOLCHAIN_PATH`指向解压后的`工具链`(步骤1下载的工具)的路径
    + 将`LISTENAI_TOOLS_PATH`指向解压后的`listenai工具包`(步骤2下载的工具)路径
> 目前仅支持`linux`平台,推荐使用`ubuntu 18.04`以上版本

## 快速开始
编译helloworld工程
### 编译
在`sdk`的根目录下执行命令
```
./build.sh -S samples/helloworld -C
```
命令说明:
- `-S` 指定项目源码路径
- `-C` 清理构建目录

编译成功后会在`build`目录下生成构建的产物

### 烧录
烧录工具位于`tools/burn/cskburn`

将串口板连接板子, 开发板的Tx脚为PA2, RX脚为PA3, 按住BOOT脚后复位开发板, 进入到烧录模式

> 每次重新烧录前, 都需要执行按住BOOT脚后复位开发板, 进入到烧录模式

cskburn已经支持了控制DTR和RTS的功能,将开发板的BOOT脚接入串口板的RTS脚, 将开发板的REST脚接入串口板的DTR脚,即可实现`自动烧录`

运行命令烧录程序
```
./tools/burn/cskburn -s /dev/ttyUSB0 -b 3000000 0x0 build/helloworld.bin
```
命令说明:
- `-s` 指定烧录设备
- `-b` 指定烧录设备的波特率
- `0x0` 指定烧录的起始地址, 该值为基于`0x30000000`(flash的起始地址)的偏移地址
- `build/helloworld.bin`: 指定烧录的文件

关于`cskburn`的更多使用见[cskburn](../tools/burn/README.MD)

烧录后复位即可看到如下日志:
```
********arcs boot on hart id:1********
boot hart:1
Hello, world!
```

## 工程创建

+ Kconfig文件中必须包含以下代码, 此代码用于添加各个模块
    ```Kconfig
    osource "$LISTENAI_MODULES"
    ```

+ prj.conf文件用于设置项目的配置
    ```prj.conf
    # 项目可根据需要在此文件中设置对应的配置
    ```

+ CMakeLists.txt为项目的顶级目录
    ```
    cmake_minimum_required(VERSION 3.13)

    set(LISTENAI_MODULES_DIR_LIST
        $ENV{ARCS_BASE}
    )

    set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

    find_package(listenai-cmake REQUIRED HINTS $ENV{ARCS_BASE})

    project(helloworld)

    listenai_add_executable(${PROJECT_NAME})

    target_sources(${PROJECT_NAME} PRIVATE src/main.c)
    ```

    `LISTENAI_MODULES_DIR_LIST`是一个列表, 用于指定需要扫描的模块的路径, 构建时,会将递归扫描该列表中的目录, 并将目录中的顶级CMakeLists.txt加入到构建系统中

## 工程配置

1. 可在工程顶级目录中的`prj.conf`文件中进行文本化配置
2. 可通过`./build.sh -t menuconfig`命令进行图形化配置

> 注意
>
> 当项目目录同时存在`.config`文件和`prj.conf`文件时, `.config`文件会被覆盖`prj.conf`文件中的配置
> 运行`menuconfig`时, 可选择将`.config`文件保存到工程目录下

## 动态内存

### 系统堆
`include` 头文件`sysheap.h`可使用适配好的系统堆, 系统堆的接口都是线程安全的

#### SRAM内存堆接口
+ `inram_malloc`
+ `inram_calloc`
+ `inram_realloc`
+ `inram_free`

可通过配置`CONFIG_HEAP_SIZE`来调整`SRAM`内存堆的大小
#### PSRAM内存堆接口
+ `psram_malloc`或`exram_malloc`
+ `psram_calloc`或`exram_calloc`
+ `psram_realloc`或`exram_realloc`
+ `psram_free`或`exram_free`

可通过`CONFIG_PSRAM_HEAP_SIZE`来调整`PSRAM`内存堆的大小

### libc动态内存

1. libc中的`malloc`, `calloc`, `free,` `realloc`函数都已经被重定向到到了`sysheap`中, 且是线程安全的, 默认`malloc`接口是从`PSRAM`中的内存堆中分配的.

### freertos动态内存
1. `FreeRTOS`的`pvPortMalloc`等动态内存接口适配为使用的`libc`中的`malloc`接口,因`malloc`接口已经被重新定, 因此`FreeRTOS`中的涉及到的动态内存分配也是用`PSRAM`的内存堆进行分配的

> 注意
>
> 1. `PSRAM`内存是默认开了`DCACHE`的, 在涉及到使用`psram`内存进行跨核通信以及`DMA`传输时,请务必确保`CACHE`一致性.
>
> 2. `SRAM`的整个内存空间默认是`NO-CACHE`的

## 链接脚本
默认的链接脚本位于`${ARCS_BASE}/startup/arcs/system.ld`, 若要使用工程自定义的链接脚本, 可以通过配置`CONFIG_ARCS_STARTUP_CUSTOM_LINKER_FILE=y`, 并通过cmake宏`listenai_set_linker_script`设置链接脚本的路径.

> 提示
>
> 使用`listenai_set_linker_script`宏指定的链接脚本中可以使用`autoconf.h`文件中的宏定义
